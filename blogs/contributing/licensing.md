# 授權與署名

## 三個要點

| 條件 | 使用與改作時要做的事 |
| --- | --- |
| BY：姓名標示 | 保留必要的作者與授權資訊、提供來源與授權連結，並標示改動 |
| NC：非商業性 | 使用不得主要以商業利益或金錢報酬為目的；不能只以「有沒有收費」判斷 |
| SA：相同方式分享 | 分享改作時，依條文採相同或相容授權 |

不要以額外條款或技術措施限制授權已允許的使用。授權不會一併授予肖像、隱私或商標權，也不能讓原本無權公開的學生資料變得可以公開。詳見[官方授權摘要](https://creativecommons.org/licenses/by-nc-sa/4.0/deed.zh-hant)。

## 本專案與 OSS 的用語

CC BY-NC-SA 限制商業使用；[OSI 的開源定義](https://opensource.org/osd)要求不得限制商業領域使用或自由再散布，因此本專案使用「公開協作專案」描述，不標示為 OSI 核准的開源軟體。

[Creative Commons 官方 FAQ](https://creativecommons.org/faq/#can-i-apply-a-creative-commons-license-to-software)不建議將 CC 授權用於軟體，因其沒有軟體授權常見的原始碼散布與專利等專門規定。本次依負責人的指定保留 CC BY-NC-SA，沒有另替程式碼選 MIT 或其他授權；若未來希望符合 OSS 定義，需另行決定程式碼授權及範圍。

## 提交前確認自己的權利

原創貢獻請確認自己有權按 CC BY-NC-SA 4.0 公開，並保留你希望使用的適當署名。涉及共同創作、學校或他人權利時，先請老師或負責人確認。不得替同學、學校或外部作者自行承諾授權。

既有成員、logo 與頭像仍需盤點來源與使用權；本次加入 LICENSE 不代表盤點已完成。缺乏權利依據的素材，須由維護者確認、替換或移除，不能直接宣稱全站所有內容都能依同一授權重用。

## 第三方套件與素材

VitePress 與其他 npm 依賴保留各自的授權；根目錄 LICENSE 不會覆蓋它們。外部圖片、字型、程式片段或文章也依原授權處理。新增前確認允許本專案的使用與散布方式，保留必要聲明；不確定相容性時先詢問維護者。

新增第三方素材時，在檔案旁或同資料夾的來源說明檔保留以下資料，PR 同時摘要：

| 欄位 | 需記錄的內容 |
| --- | --- |
| 本地位置 | 實際檔案路徑，讓讀者知道聲明對應哪個素材 |
| 作品與作者 | 原作品名稱、原作者或權利人 |
| 來源 | 可追溯的原始頁面網址 |
| 授權依據 | 授權名稱、版本、條文連結，或已確認的個別許可狀態 |
| 改動 | 是否裁切、翻譯、改色或改寫 |

只有 PR 留言不足以代替需要隨檔案散布的授權聲明。私人許可文件保存在老師指定的非公開位置，公開文件僅保留適合揭露的權利說明。

## 重用本站內容的署名範例

以下文字僅示範格式；實際重用時須核對該頁作者、來源與例外素材：

```text
來源：FHCST 山城資訊工作隊官方網站及 blog／原作品所列作者
原始網址：https://github.com/fhcst/fhcst.github.io
授權：CC BY-NC-SA 4.0
授權連結：https://creativecommons.org/licenses/by-nc-sa/4.0/
修改說明：依實際情況填寫，例如重新編排並補充操作說明。
第三方素材：依原作品標示另列。
```

有商業使用需求或無法判定的使用情境，先向相關權利人詢問。不要把網站公開、學校用途或附上作者名字，當成自動符合所有授權條件。
